*Architecting the Cognitive Chassis for the Autonomous Mathematical Discovery Engine*
# 1. Executive Summary & Strategic Mandate
Phase 1 represents the critical transition from the static, foundational infrastructure established in Phase 0 to the first dynamic "heartbeat" of the multi-agent mathematical reasoning system. The primary objective of this phase is not to achieve broad mathematical capability, but to construct a **reliable, hallucination-resistant reasoning core**—the foundational Cognitive Chassis upon which all future intelligence will be built.
📚 Reference: Phase_1_Coding_Strategy__Architecting_the_Cognitive_Chassis.docx, Section 1.0
The central architectural mission is to solve the fundamental reliability crisis in AI: standard systems generate "plausible but incorrect answers." The governing principle is to ***"Shackle Neural Creativity to Symbolic Rigor"***—meaning every creative or intuitive step generated by any component must be validated by a deterministic, symbolic system before it can be accepted as truth.
📚 Reference: Phase_1_is_the_construction_of_the_Cognitive_Chassis.docx, Introduction
## 1.1 The Orchestrator-Prover-Verifier Loop
Phase 1 establishes the core operational pattern of the entire system: the **Orchestrator-Prover-Verifier loop**. This feedback mechanism is the fundamental engine that guarantees the system can legally and verifiably solve a problem without hallucinating. The loop enforces that from the very first moment of operation, neural creativity is shackled to symbolic rigor.
📚 Reference: phases_0-6_for_the_Autonomous_Mathematical_Discovery_Engine.docx, Phase 1 Section

All Phase 1 agents must adhere to two non-negotiable communication standards established in Phase 0:

# 3. Build Order: Step-by-Step Implementation
## STEP 1: The Gatekeepers (Problem Analysis Team)
### WHAT: Input Sanitization & Classification
Construct the interface that sanitizes and structures chaotic natural language into strict mathematical objects before the Orchestrator ever sees them. This prevents the "Garbage In, Garbage Out" failure mode by ensuring no ambiguous text enters the reasoning core.
### WHY: Preventing Ambiguity at the Source
Raw text or LaTeX conveys *presentation* (how it looks) rather than *content* (what it means). The string "x²" lacks true semantic meaning—it could represent a variable squared, a label, or decoration. The Problem Analysis Team ensures that a "derivative" is understood as a mathematical operator with specific semantics, not merely a text string.
📚 Reference: Phase_0_Build_Order_Breakdown.docx, Step 1: The Semantic Substrate
### HOW: Agent Implementation
**Agent 1.1: Syntax Parser & Autoformalizer**
- Directive: Implement an agent specialized in translating natural language (e.g., "Find the derivative of x squared") and LaTeX into OMDoc/OpenMath standards.
- Architecture: Functions as the system's "transducer." Must parse input text and output structured expression trees. Converts "integral of x" into OpenMath object ensuring downstream agents receive semantic objects, not text strings.
📚 Reference: Phase_1_is_designated_as_the_construction_of_the_Cognitive_Chassis.docx, Agent 1.1
**Agent 1.2: Structure Recognizer**
- Directive: Implement the meta-classifier that tags problem type.
- Logic: This agent does not solve; it categorizes. Must distinguish between Computation ("Calculate this"), Proof ("Show that..."), and Optimization ("Find the maximum..."). Tag is appended to problem metadata on Blackboard for Orchestrator's routing logic.
📚 Reference: Phase_1_is_the_construction_of_the_Cognitive_Chassis.docx, Step 1, Action 1.2
### CODE: Problem Analysis Team Implementation
# problem_analysis.py - The Gatekeepers
from dataclasses import dataclass
from enum import Enum
from typing import Any, Optional
import re

class ProblemType(Enum):
    COMPUTATION = 'computation'  # "Calculate this"
    PROOF = 'proof'              # "Show that..."
    OPTIMIZATION = 'optimization' # "Find the maximum..."

@dataclass
class OMDocObject:
    """Structured mathematical object in OMDoc format"""
    expression_tree: Any  # Parsed mathematical structure
    problem_type: ProblemType
    domain_tag: str  # e.g., 'Calculus', 'Algebra'
    raw_input: str
    metadata: dict

class SyntaxParserAgent:
    """Agent 1.1: Transduces natural language to OMDoc"""
    def parse(self, raw_input: str) -> OMDocObject:
        # Convert text -> expression tree
        expression = self._parse_to_expression_tree(raw_input)
        return OMDocObject(
            expression_tree=expression,
            problem_type=None,  # Set by StructureRecognizer
            domain_tag='',  raw_input=raw_input, metadata={}
        )

class StructureRecognizerAgent:
    """Agent 1.2: Meta-classifier that tags problem type"""
    def classify(self, omdoc: OMDocObject) -> OMDocObject:
        # Classify based on keywords and structure
        text = omdoc.raw_input.lower()
        if any(kw in text for kw in ['prove', 'show that']):
            omdoc.problem_type = ProblemType.PROOF
        elif any(kw in text for kw in ['maximize', 'minimize']):
            omdoc.problem_type = ProblemType.OPTIMIZATION
        else:
            omdoc.problem_type = ProblemType.COMPUTATION
        # Tag domain
        if any(kw in text for kw in ['derivative', 'integral']):
            omdoc.domain_tag = 'Calculus'
        return omdoc

## STEP 2: The Central Nervous System (Main Orchestrator)
### WHAT: Tier 1 Management Agent
Instantiate the Tier 1 agent—the "General Contractor" whose sole job is management, enforcing the strict separation of Problem Understanding from Problem Solving.
### WHY: Architectural Discipline for Scaling
The Orchestrator must manage, never solve. By hard-coding the "Non-Intervention" directive—forbidding the Orchestrator from performing calculations—the system enforces the architectural discipline required for scaling to 50+ agents in Phase 2. This separation ensures that when the system scales, the management layer remains clean and uncontaminated by computational concerns.
📚 Reference: Phase_1_Coding_Strategy__Architecting_the_Cognitive_Chassis.docx, Section 3.2
### HOW: Agent Implementation
**Agent 2.1: Decomposition Engine (Planner)**
- Directive: Program the Orchestrator with Hierarchical Task Network (HTN) logic. Must be capable of breaking requests into sub-goals (e.g., "First simplify, then integrate").
- Critical Constraint: Hard-code "Non-Intervention" directive. Orchestrator is strictly forbidden from performing calculations. If it detects "2+2", it must delegate, never compute.
📚 Reference: Phase_1_is_designated_as_the_construction_of_the_Cognitive_Chassis.docx, Agent 2.1
**Agent 2.2: Routing Logic (The Rolodex)**
- Directive: Connect Orchestrator to Directory Facilitator (DF) built in Phase 0.
- Mechanism: When Orchestrator identifies a "Calculus" tag from the Analysis Team, it queries the DF for available agents with that capability. Currently finds only "Pilot Solver" but this dynamic lookup ensures that when 50 agents are added in Phase 2, Orchestrator detects them automatically without code changes.
📚 Reference: Phase_1_is_the_construction_of_the_Cognitive_Chassis.docx, Step 2, Action 2.2
### CODE: Main Orchestrator Implementation
# orchestrator.py - The Central Nervous System
class MainOrchestrator:
    """Tier 1 Agent: General Contractor - NEVER COMPUTES"""
    def __init__(self, df: DirectoryFacilitator, blackboard: Blackboard):
        self.df = df
        self.blackboard = blackboard
        self.NON_INTERVENTION = True  # HARD-CODED CONSTRAINT

    def process(self, omdoc: OMDocObject) -> str:
        # CRITICAL: Never compute, always delegate
        if self.NON_INTERVENTION:
            # Step 1: Decompose if complex (HTN logic)
            subtasks = self._decompose(omdoc)

            # Step 2: Query DF for capable agent
            agents = self.df.search(
                service_type=f'math.{omdoc.domain_tag.lower()}'
            )
            if not agents:
                raise NoAgentAvailable(omdoc.domain_tag)

            # Step 3: Post task to Blackboard
            entry = BlackboardEntry(
                entry_type='task',
                content=omdoc,
                status=EntryStatus.PENDING,
                tags=[omdoc.domain_tag]
            )
            self.blackboard.post(entry)

            # Step 4: Wait for verified result
            return self._await_verified_result(entry.entry_id)

    def _decompose(self, omdoc: OMDocObject) -> list:
        """HTN decomposition - break into sub-goals"""
        # Example: 'simplify then integrate' -> [simplify, integrate]
        return [omdoc]  # Phase 1: single-step tasks only

## STEP 3: The Pilot Solver (Symbolic Wrapper)
### WHAT: Temporary Stand-In Worker
Create a temporary "stand-in" for the future workforce. A functional worker is needed to test the pipeline, even before building the specialized Tier 2 Supervisors of Phase 2.
### WHY: The "Tracer Bullet" Strategy
This agent serves as the "tracer bullet." It proves that a mathematical payload can travel the full circuit: User → Orchestrator → Blackboard → Solver → Back. This verifies the plumbing of the entire system before complexity is added. The strategic purpose is architectural validation, not mathematical capability.
📚 Reference: Phase_1_is_designated_as_the_construction_of_the_Cognitive_Chassis.docx, Section 3: The Pilot Solver
### HOW: Agent Implementation
**Agent 3.1: SymPy Wrapper Agent**
- Directive: Encapsulate a robust Computer Algebra System (CAS), specifically SymPy, inside a standard agent shell.
- Function: Acts as the "Prover" or "Executor." Receives OMDoc inputs from Blackboard, executes deterministic symbolic operations (sympy.diff, sympy.integrate), posts result back to Blackboard.
- Registration: Must register service capabilities with Directory Facilitator using service_type='math.calculus' pattern.
📚 Reference: Phase_1_is_the_construction_of_the_Cognitive_Chassis.docx, Step 3, Action 3.1
### CODE: Pilot Solver Implementation
# pilot_solver.py - The Tracer Bullet
import sympy as sp
from sympy.parsing.sympy_parser import parse_expr

class PilotSolverAgent:
    """Temporary stand-in wrapping SymPy CAS"""

    def __init__(self, df: DirectoryFacilitator, blackboard: Blackboard):
        self.df = df
        self.blackboard = blackboard
        self._register_services()
        self._subscribe_to_tasks()

    def _register_services(self):
        """Register capabilities with Directory Facilitator"""
        self.df.register(ServiceRegistration(
            service_type='math.calculus',
            agent_id='pilot_solver_001',
            properties={'type': 'symbolic', 'engine': 'sympy'}
        ))

    def _subscribe_to_tasks(self):
        """Subscribe to Calculus tasks on Blackboard"""
        self.blackboard.subscribe('Calculus', self.on_task)

    def on_task(self, entry: BlackboardEntry):
        """Handle incoming task from Blackboard"""
        omdoc = entry.content
        result = self._execute(omdoc)

        # Post candidate result to Blackboard
        self.blackboard.post(BlackboardEntry(
            entry_type='candidate_result',
            content=result,
            status=EntryStatus.PENDING,  # Awaits verification
            parent_entry=entry.entry_id,
            tags=['verification_needed']
        ))

    def _execute(self, omdoc: OMDocObject):
        """Execute symbolic operation via SymPy"""
        x = sp.Symbol('x')
        expr = omdoc.expression_tree
        if 'derivative' in omdoc.raw_input.lower():
            return sp.diff(expr, x)
        elif 'integral' in omdoc.raw_input.lower():
            return sp.integrate(expr, x)

## STEP 4: The Immune System (Verification Core)
### WHAT: Ax-Prover Pattern Implementation
Implement the Ax-Prover pattern immediately. This is the **most critical step for preventing hallucination**. No result from the Pilot Solver is allowed to leave the system until this team stamps it "Approved."
### WHY: The Conscience of the System
The Verification Core is the system's "conscience"—the component that enforces mathematical truth. Standard AI systems generate "plausible but incorrect answers." By implementing formal verification, every intuitive step generated by the Pilot Solver is validated by a deterministic, symbolic system before being accepted as truth. The system never trusts; it always verifies.
📚 Reference: Phase_1_Coding_Strategy__Architecting_the_Cognitive_Chassis.docx, Section 3.4
### HOW: Two-Layered Defense
**Agent 4.1: Logic Checker (First Line of Defense)**
- Directive: Build a rule-based agent that inspects the logical flow of the solution.
- Logic: Checks for "illegal moves" such as: dividing by a variable without confirming it is non-zero, applying a real-domain logarithm to a negative number. Addresses the "Assumption Gap" early.
📚 Reference: Phase_1_is_designated_as_the_construction_of_the_Cognitive_Chassis.docx, Agent 4.1
**Agent 4.2: Formal Verifier Wrapper (Second Line of Defense)**
- Directive: Wrap a formal theorem prover (Lean 4, Coq, or Isabelle) into a "Verifier Agent."
- The Neural-Symbolic Loop: Configure so Pilot Solver's output is treated as "candidate proof." Verifier Agent attempts to compile:
- If it compiles: Result marked STATUS: VERIFIED, released to user.
- If it fails: ERROR FLAG raised on Blackboard, triggering feedback loop to Orchestrator to retry.
📚 Reference: Phase_1_is_the_construction_of_the_Cognitive_Chassis.docx, Step 4, Action 4.2
### CODE: Verification Core Implementation
# verification_core.py - The Immune System

class LogicCheckerAgent:
    """First Line of Defense: Rule-based validation"""

    ILLEGAL_MOVES = [
        'division_by_zero',
        'log_of_negative',
        'sqrt_of_negative_real',
        'undefined_limit'
    ]

    def check(self, candidate_result, original_omdoc) -> tuple:
        """Check for illegal moves in solution"""
        violations = []
        # Check division by potentially-zero denominators
        if self._has_division(candidate_result):
            if not self._denominator_verified_nonzero(candidate_result):
                violations.append('division_by_zero')
        return (len(violations) == 0, violations)

class FormalVerifierAgent:
    """Second Line of Defense: Theorem prover wrapper"""

    def __init__(self, blackboard: Blackboard):
        self.blackboard = blackboard
        self.blackboard.subscribe('verification_needed', self.on_candidate)

    def on_candidate(self, entry: BlackboardEntry):
        """Attempt to formally verify candidate proof"""
        candidate = entry.content
        try:
            verified = self._compile_in_lean(candidate)
            if verified:
                # SUCCESS: Mark as verified
                entry.status = EntryStatus.VERIFIED
                self.blackboard.update(entry)
            else:
                # FAILURE: Raise error flag for retry
                entry.status = EntryStatus.FAILED
                self.blackboard.post(BlackboardEntry(
                    entry_type='error_flag',
                    content={'reason': 'verification_failed'},
                    parent_entry=entry.parent_entry
                ))
        except CompilationError as e:
            entry.status = EntryStatus.FAILED

# 4. Phase 1 Deliverables & Success Criteria
## 4.1 Final Deliverable: Architecturally Complete, Mathematically Limited
At the conclusion of Phase 1, the system is **architecturally complete** with a functional and verified reasoning loop, but remains **mathematically limited** as its capabilities are bound to the SymPy library. This outcome is not a shortcoming but the *intended design*, prioritizing the perfection of the chassis before installing more powerful engines.
📚 Reference: Phase_1_Coding_Strategy__Architecting_the_Cognitive_Chassis.docx, Section 5.0
## 4.2 Critical Separations of Concern
Two critical separations have been hard-coded into the system's architecture:

| Separation | Implementation |
| --- | --- |
| Planning from Execution | Orchestrator responsible for planning, decomposition, delegation. Pilot Solver responsible for execution. The Orchestrator manages; it never solves. |
| Intuition from Verification | Pilot Solver provides candidate answer (the "intuition"). Verification Core proves correctness and freedom from logical flaws. The system never trusts; it always verifies. |
