=========================================
SYMBO – NEXT-STEPS ROADMAP (COPY-PASTE)
=========================================

GOAL
----
Harden parsing, routing, and special-function/probability handling so the
extreme asymptotic tests are reachable and correctly classified before solving.

PHASE 1 – PARSER & INPUT NORMALIZATION
--------------------------------------

1.1 Parentheses & token robustness
----------------------------------
- Implement a pre-parse “balancer”:
  - Count (), [], {} in the raw input.
  - If mismatch is ±1 at the end of an expression, attempt a minimal fix:
    - Insert or remove a single RPAREN/LPAREN at the end.
    - Re-run the parser.
  - Only fail if both raw and “repaired” parses fail.
- Log a warning like:
  - "[parser] Auto-corrected parentheses in input; original='...', corrected='...'."

1.2 Multi-line & comments
-------------------------
- Before tokenization:
  - Join consecutive lines that start/continue a math call:
    - e.g. "limit(" ... newline ... ")"
  - Strip comments safely:
    - Remove everything from "#" to end-of-line, but only outside string/parenthesis contexts.
- Ensure a single expression string is passed to the parser for:
  - limit(...), integrate(...), diophantine(...).

1.3 Special-function tokens
---------------------------
- Extend lexer keyword table:
  - Treat these as FUNCTION tokens: Gamma, zeta, erf, BesselJ, Li, Ei, Ai, Bi, Phi, P, M_X.
- This reduces “Expected RPAREN, got LPAREN/SYMBOL/COMMA” errors in:
  - zeta(1 + 1/x), Li(x), erf(...), BesselJ(...), P(N(0,1) > x), M_X(t), etc.


PHASE 2 – DOMAIN CLASSIFICATION & ROUTING
-----------------------------------------

2.1 Keep arithmetic_specialist numeric-only
-------------------------------------------
- Hard rule:
  - If top-level AST is limit(...) or integrate(...), NEVER route to arithmetic_specialist_001.
- arithmetic_specialist_001 may only receive:
  - Pure numeric/rational expressions or integer arithmetic tasks.
- Update structure_recognizer_001:
  - Any expression with "limit(" or "integrate(" at top-level:
    - domain = Calculus, specialist_hint = limit_specialist or integration_specialist.

2.2 Special-functions & probability tags
----------------------------------------
- Extend structure_recognizer_001:
  - If any of {Gamma, zeta, erf, BesselJ, Li, Ai, Bi, Ei} appear:
    - add tag: "special_functions".
  - If any of {P(…), Phi, N(0,1), M_X} appear:
    - add tag: "probability".
- Routing:
  - limit + special_functions → limit_specialist_001 with special-function module.
  - limit + probability → probability_limit_specialist_001 (new).
  - diophantine(...) → diophantine_specialist_001 (new), not generic Algebra.

2.3 Diophantine specialist
--------------------------
- Implement diophantine_specialist_001:
  - Input: diophantine(expr) with polynomial expr in integer variables.
  - Use SymPy’s diophantine solver internally.
  - Output:
    - solutions (possibly parametric),
    - or "no_solution" / "unknown_hard" with clear metadata.


PHASE 3 – SPECIAL-FUNCTION & ASYMPTOTIC MICRO-LIBRARY
-----------------------------------------------------

3.1 Encode key asymptotic patterns
----------------------------------
Create a small table of known expansions (symbolic templates):

- Gamma / Stirling:
  - log(Gamma(x)) ~ (x - 1/2)*log(x) - x + (1/2)*log(2*pi) + 1/(12*x) - 1/(360*x**3) + ...
  - Gamma(x + a)/Gamma(x) ~ x**a * (1 + a*(a-1)/(2*x) + a*(a-1)*(a-2)/(6*x**2) + ...).

- Zeta near 1:
  - zeta(1 + 1/x) ~ x + gamma + 1/(2*x) - 1/(12*x**2) + 1/(120*x**4) + ...

- Erf:
  - Near 0: erf(x) ~ 2*x/sqrt(pi) - 2*x**3/(3*sqrt(pi)) + ...
  - Large x: 1 - erf(x) ~ exp(-x**2)/(sqrt(pi)*x) * (1 - 1/(2*x**2) + 3/(4*x**4) + ...).

- Bessel J/Y (order 0, large x):
  - J0(x) ~ sqrt(2/(pi*x))*cos(x - pi/4) - (1/(8))*sqrt(2/(pi*x**3))*sin(x - pi/4) + ...
  - Y0(x) ~ sqrt(2/(pi*x))*sin(x - pi/4) + (1/(8))*sqrt(2/(pi*x**3))*cos(x - pi/4) + ...

- Li(x):
  - Li(x) ~ x/log(x) + x/(log(x))**2 + 2*x/(log(x))**3 + 6*x/(log(x))**4 + ...

3.2 Hook into limit_specialist
------------------------------
- In limit_specialist_001:
  - When generic limit evaluation fails or is disabled:
    - Normalize expression (pull out x→∞, etc.).
    - Pattern-match against the asymptotic table.
    - Substitute truncated series and compute the limit of the resulting rational/log expression.
- Annotate results with:
  - source = "asymptotic_pattern",
  - assumptions = { "x": "→∞", ... }.


PHASE 4 – PROBABILITY / STATISTICS LAYER
----------------------------------------

4.1 Probability_specialist_001
------------------------------
- Responsibilities:
  - Interpret:
    - P(N(0,1) > x), Phi(x), M_X(t), log(M_X(t)), etc.
  - Provide:
    - Normal tail asymptotic:
      P(N(0,1) > x) ~ (1/(x*sqrt(2*pi))) * exp(-x**2/2) * (1 - 1/x**2 + ...).
    - MGF/CGF expansions:
      log(M_X(t)) ~ mu*t + sigma**2*t**2/2 + kappa_3*t**3/6 + kappa_4*t**4/24 + ...

4.2 Probability limits
----------------------
- For tests like:
  - limit((P(N(0,1) > x)*x*sqrt(2*pi)*exp(x**2/2) - 1 + 1/x**2)*x**2, x, oo)
  - limit((log(M_X(t)) - mu*t - sigma**2*t**2/2 - kappa_3*t**3/6 - kappa_4*t**4/24)/t**5, t, 0)
- Use the above expansions to:
  - Reduce to polynomial/rational limits (handled by limit_specialist_001).
- Return:
  - value + metadata: { "source": "probability_asymptotic", "assumptions": {...} }.


PHASE 5 – IMPROPER INTEGRALS & CONVERGENCE
------------------------------------------

5.1 Classification of improper integrals
----------------------------------------
- For integrals like:
  - integrate((e**(-x) - 1/(1 + x)) / x, (x, 0, oo))
- Implement steps:
  - Analyze series near 0 and ∞:
    - Expand integrand around 0 and for large x.
    - Compare with standard p-integral or log-divergence tests.
  - Decide:
    - convergent, conditionally_convergent (PV), divergent, or unknown.
- Attach metadata:
  - { "convergence": "...", "method": "analytic|numeric|mixed" }.

5.2 Keep Dirichlet-style reporting
----------------------------------
- For known integrals like ∫_0^∞ sin(x)/x * log(x) dx:
  - Keep the descriptive label:
    - "conditionally convergent, value = pi/2 (Dirichlet integral)".
  - Ensure this label is structured:
    - {"value": pi/2, "convergence": "conditional", "name": "Dirichlet"}.
