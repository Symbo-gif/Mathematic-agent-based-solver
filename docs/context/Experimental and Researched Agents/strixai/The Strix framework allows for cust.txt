The Strix framework allows for custom tools to be integrated, offering a unified interface for agents to interact with diverse functionalities. This is primarily managed by the files within the [`strix/tools`](%2Fusestrix%2Fstrix%2Fstrix%2Ftools) directory, specifically through the [`registry.py`](%2Fusestrix%2Fstrix%2Fcontainers%2FDockerfile#L172) and [`executor.py`](%2Fusestrix%2Fstrix%2Fcontainers%2FDockerfile#L172) modules as described in [Tool Management and Execution Framework](#strix-tools-and-capabilities-tool-management-and-execution-framework).

To add a new custom tool:

1.  **Register the Tool:** You would use the [`register_tool`](%2Fusestrix%2Fstrix%2Fstrix%2Ftools%2Fregistry.py#L98) function, found in `usestrix/strix/strix/tools/registry.py`. This function associates your custom tool with metadata such as its name, module, and an optional XML schema definition. The XML schema is crucial for generating structured prompts that enable AI agents to understand and select the tool.
    ```python
    from strix.tools.registry import register_tool

    @register_tool
    def my_custom_tool(argument1: str, argument2: int, agent_state=None) -> str:
        """
        Description of what my custom tool does.
        :param argument1: A string parameter.
        :param argument2: An integer parameter.
        :return: A string result.
        """
        # Your tool's logic here
        result = f"Custom tool executed with arg1: {argument1}, arg2: {argument2}"
        if agent_state:
            agent_state.add_message("tool_output", result)
        return result
    ```
    You can also specify whether the tool should be executed in a sandboxed environment using the [`sandbox_execution`](%2Fusestrix%2Fstrix%2Fstrix%2Ftools%2Fregistry.py#L99) parameter in the [`@register_tool`](%2Fusestrix%2Fstrix%2Fstrix%2Ftools%2Fproxy%2Fproxy_actions.py#L11) decorator.

2.  **Define XML Schema (Optional but Recommended):** For better LLM integration, it's recommended to define an XML schema for your tool. This schema should be placed in an XML file named `your_tool_module_name_schema.xml` in the same directory as your tool's Python file. This schema helps the LLM understand how to use your tool, including its name, description, and parameters. The [`_load_xml_schema`](%2Fusestrix%2Fstrix%2Fstrix%2Ftools%2Fregistry.py#L42) function in `usestrix/strix/strix/tools/registry.py` handles loading these.

3.  **Execution:** Tool execution is orchestrated by the [`execute_tool`](%2Fusestrix%2Fstrix%2Fstrix%2Ftools%2Fexecutor.py#L24) function in `usestrix/strix/strix/tools/executor.py`. This function dispatches execution either locally or within a sandboxed environment. For local execution, it directly invokes the tool function after converting arguments using the [`convert_arguments`](%2Fusestrix%2Fstrix%2Fstrix%2Ftools%2Fargument_parser.py#L15) utility from `usestrix/strix/strix/tools/argument_parser.py`, which leverages Python's [`inspect.signature`](%2Fusestrix%2Fstrix%2Fstrix%2Ftools%2Fargument_parser.py#L17) to cast string-based inputs to appropriate Python types.

The core [`BaseAgent`](%2Fusestrix%2Fstrix%2Fstrix%2Fagents%2Fbase_agent.py#L49) class includes an [`agent_loop`](%2Fusestrix%2Fstrix%2Fstrix%2Fagents%2Fbase_agent.py#L153) method that processes LLM responses and executes tools, as described in [Base Agent Architecture and Execution Loop](#agent-operations-and-lifecycle-management-base-agent-architecture-and-execution-loop). If the LLM output includes tool invocations, the [`_execute_actions`](%2Fusestrix%2Fstrix%2Fstrix%2Fagents%2Fbase_agent.py#L391) method processes these by creating an asynchronous task to run the specified tools, updating the agent's state with the results. The parsing of LLM outputs to extract tool invocations is handled by [`parse_tool_invocations`](%2Fusestrix%2Fstrix%2Fstrix%2Fllm%2Futils.py#L20) in `usestrix/strix/strix/llm/utils.py`, as detailed in [LLM Output Parsing and Tool Invocation](#large-language-model-llm-integration-llm-output-parsing-and-tool-invocation).

Custom tools can also have specialized renderers for the Textual User Interface (TUI) to display their actions and outputs, by inheriting from [`BaseToolRenderer`](%2Fusestrix%2Fstrix%2Fstrix%2Finterface%2Ftool_components%2Fbase_renderer.py#L8) and associating them with the tool via the [`@register_tool_renderer`](%2Fusestrix%2Fstrix%2Fstrix%2Finterface%2Ftool_components%2Fproxy_renderer.py#L9) decorator as described in [Specialized Tool Renderers and Syntax Highlighting](#user-interface-components-for-tool-interactions-specialized-tool-renderers-and-syntax-highlighting). This integration into the [`ToolTUIRegistry`](%2Fusestrix%2Fstrix%2Fstrix%2Finterface%2Ftool_components%2Fregistry.py#L8) allows the system to dynamically select the appropriate renderer.
